# Publication checklist

This is a list of required evidence, not a publication receipt or permission
to publish. The foundation is prepared locally. Commits, pushes, hosting
changes, purchases, and external messages require their own authority.

## Review the exact local candidate

- Preserve the original preparation history privately.
- Export the intended candidate without Git history and keep its manifest outside it.
- Scan filenames, content, metadata, symlinks, and every outgoing byte for secrets and excluded private material.
- Run the relevant local tooling checks and retain the commands, results, and exact candidate identity.
- Obtain a review of the actual files and diff by a frontier model from a different company than the builder's. Fix material findings, retest, and obtain recheck.
- Verify that licences and required notices are retained and that no application implementation has entered the foundation.

A local result refers to the named snapshot only. It does not certify
historical attribution, a future signed commit, or a running product.

## Complete separately authorised hosted work

- Approve the concrete initial-upload procedure, including attribution, signatures, outgoing history, and the initial-upload review limitation.
- Verify the repository identity, collaborator-only contribution settings, signing-key registration, and effective rulesets.
- Read actual required check names and their originating apps from hosted runs. Confirm review evidence and security evidence bind to the final revision.
- Obtain Copilot review on each actual hosted pull request revision and resolve its findings. Record the first-root review limitation explicitly: a later small pull request is not review of the complete initial foundation.
- Test direct-push refusal, unsigned-commit refusal, stale-review refusal, and failure or pending-check merge refusal with the actual working credentials.
- Verify merge-commit-only behaviour and the final signature.
- Test the receiving security mailbox and private vulnerability-reporting route.
- Publish the curated technical evidence digest and adjudicated review verdicts, or keep that deliverable explicitly outstanding.

An absent required status remains pending and blocks merging. A local
configuration file does not establish the effective hosted policy.

## Keep later holds separate

The full build-loop rehearsal remains required before product code. A green
conformance proof is required before protected-component merges, and the
sandbox's final contract requires approval before implementation. The licence
exception and CLA remain drafts. An independent restore rehearsal and measured
recovery evidence remain release requirements. None is completed by this
checklist.
